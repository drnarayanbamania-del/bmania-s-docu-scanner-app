# Bamania's Scanner 1.0.2

First signed Android build of Bamania's Scanner, plus the fixes that came out of
testing the scan → save → export flow end to end.

## Highlights

- **Square launcher icon.** The home screen used to show the wide logo banner
  letterboxed into an empty tile. It now uses the brand mark on a square icon,
  with a proper adaptive icon for Android 8+.
- **Release pipeline in one command.** `deploy/release.sh` bumps the version,
  rebuilds the signed APK and packages the Hostinger upload in one go.

## Fixes

- **New pages keep the right order.** Pages took their position from the
  document's page count, so deleting a page from the middle left a gap and the
  next page reused an existing position — two pages then sorted into the same
  slot and exports came out in the wrong sequence. Pages now continue after the
  highest stored position.
- **You can leave a document again.** Saving a scan opened the document on a
  fresh navigation stack with nothing underneath, so the back arrow did nothing.
  It now returns to the dashboard.
- **The logo is a real PNG.** `assets/logo.png` was a JPEG with a `.png`
  extension. Browsers never noticed, but AAPT2 rejects it, which broke the
  Android build.

## Under the hood

- Dropped the unused `react-native-pdf-lib` (it pulls `jcenter()` and AGP 1.3.1,
  which Gradle 9 refuses to evaluate) and declared `react-native-worklets`,
  which Reanimated 4 requires.
- Added `deploy/RELEASE.md`: key backup, artifact verification against the
  signing certificate, and the Hostinger/Aptoide upload steps.
- Added the Hostinger deployment package (`.htaccess` with SPA fallback, caching
  and APK MIME type).

`apksigner verify --print-certs bamanias-scanner-1.0.2.apk`. Installing it over
1.0.0 or 1.0.1 works because the signature and package name match.

## Notes

- Scans need a network connection to upload page images to Supabase Storage. If
  an upload fails the page is kept on the device so nothing is lost, and it is
  uploaded again on the next write.
- This build has not been tested on a physical device; camera capture, gallery
  import, permissions and the Android share sheet are the areas to check first.
